# CodeCart PRO 3.0.6 — переход Bootstrap 3 → 5 (экспериментальная ветка)

Дата проверки: 19 ноября 2026.
Ветка: `experiment/bootstrap5-compat-fa7`.
Основная ветка `main` не изменена.

## Реализовано

Bootstrap 5.3.9 + Popper: по умолчанию в админке и штатных темах CodeCart и Default. Bootstrap 3.4.1 сохранён только как резервный режим по параметру `ccp_bs5=0`. Одновременного глобального подключения обеих библиотек в штатных заголовках нет.

Font Awesome Free 7.3.1 + официальный CSS v4 shims: по умолчанию вместе с Bootstrap 5. В резервном режиме остаётся прежний Font Awesome 6.7.2.

Совместимый CSS для сетки Bootstrap 3 (`xs` до 767 px; `sm` 768–991; `md` 992–1199; `lg` с 1200), панелей, вкладок, форм, кнопок, списков, таблиц и печатных элементов.

Слой JavaScript для старой разметки и API jQuery: `data-toggle`, `data-target`, `data-dismiss`, динамически добавленные элементы; модальные окна, вкладки, всплывающие меню, подсказки, popover, collapse, carousel, кнопки loading/reset.

Summernote 0.9.1: при Bootstrap 5 редактор подгружает BS5-вариант JS/CSS, поставляемый локально со шрифтами; старый редактор сохранён только для резервного режима.

Печатные формы счёта и отгрузки: заменены Bootstrap 3, Font Awesome 6 и ненужные jQuery/Bootstrap JS на CSS Bootstrap 5 и Font Awesome 7.

Связка Air Datepicker 3.6.0 + Day.js 1.11.23 + адаптер: реализована в параллельном тестовом режиме `ccp_date=air`; не включена по умолчанию, чтобы не рисковать историческими полями даты.

jQuery 3.8.0 + Migrate 3.6.0, Guzzle 7.16.3 + PSR7 2.13.4 с согласованным composer.lock, обновление Playwright — только в дополнительной ветке.

## Как проверить на тестовом стенде

Обычный запрос в этой ветке: Bootstrap 5.3.9 + Font Awesome 7.3.1.
Для сравнения старого варианта на отдельной странице: `ccp_bs5=0` в URL.
Календарь Air Datepicker: `ccp_date=air` в URL; старый календарь остаётся штатным.
Параметры не сохраняются между переходами на другие страницы. Настройка продакшен-переключателя пока не внедрялась.

## Успешные автоматические тесты

`CodeCart Modernization Pilot QA`:
- Статическая проверка наличия библиотек, их версий, синтаксиса JavaScript и выбранных PHP-контроллеров.
- Проверка старых прямых подключений Bootstrap 3 в штатных исходниках (неразрешённых подключений 0).
- Chromium: Bootstrap tabs, dropdown, collapse, modal, popover, legacy buttons, carousel conversions, динамический DOM и Bootstrap 3 сетка на 375, 650, 900, 1050, 1400 px.
- Chromium: Summernote BS5 — создание редактора, ввод HTML, уничтожение редактора на 375 и 1280 px.
- Chromium: Air Datepicker + Day.js — ввод и проверка даты/времени, секунды, строгая валидация, локализация uk/ru/en, ограничения, динамические поля на 375 и 1280 px.
- PHP: исходные контракты UniShop2 и проверка OCMOD-совместимости.
- Composer: обновление и установка Guzzle 7.16.3/PSR7 2.13.4.

## Что не удостоверено

Полная совместимость установленных сторонних модулей OpenCart/ocStore/UniShop2 в реальном браузере и с конкретной БД: они отсутствуют в стендовом окружении GitHub Actions.

Не выполнена полная E2E-проверка живого тестового магазина: оформление и оплата заказов, доставка, нестандартные OCMOD/Events, реальный checkout, реклама и интеграции. Переход на Bootstrap 5 на продакшене до этих проверок не разрешён.

Bootstrap 3 сохраняется в файловой структуре для резервного режима, это намеренно. Любое стороннее расширение, жёстко загружающее Bootstrap 3 независимо от штатных шаблонов, может вызвать конфликты.

Для сторонних модулей, которые полагаются на внутренние/private методы Bootstrap 3, адаптер может потребовать специальных исправлений; универсальная совместимость не гарантируется.

## Вердикт

**Ready for staging verification**, не **production-ready**. Штатные компоненты и зависимости переведены, контрольные браузерные тесты пройдены, но завершение *производственной* миграции требует реальной интеграционной проверки магазина.
